## 1. 背景与问题诊断

「玩家依赖性诊断」（`docs/项目现状与后续规划.md` §3.7，2026-10-07）六层评估给出：单局心流 / 次日回访 / 长线目标 = **偏弱**，投入可见性 = 薄弱。三个子项目中 ①（入口与首日体验）、②a（道友档案化）、③（长线目标与可见性，M23 修仙之路）均已落地，**次日回访这一层至今没有任何专门机制**。

现状的「每日钩子」盘点：

| 现有每日钩子 | 覆盖 | 缺口 |
|---|---|---|
| 修行任务 / 活跃度宝箱（#27） | 完成行为给奖励，需**主动玩** | 不玩就断，无「只回来看一眼」的理由 |
| 每日仙缘（广告领凡俗宝盒） | 需看广告 | 有广告疲劳，且未配 ID 前真机不可领 |
| 秘境体力（#42，15 分钟回 1 点） | 有上限、会溢出 | 溢出即浪费，**反向惩罚**（不回来也没损失感） |
| 月卡每日券（#14） | 仅付费用户 | 覆盖不到绝大多数玩家 |

**病灶：没有任何一条给「连续回来」本身发奖。** 连续登录是次日回访成本最低、行业最通用的钩子，且 M14 规格 §3.6 已明确把它列为「留下一期」。

**解法**：新增签到系统，七日轮回 + 累计里程碑，**纯本地、零平台依赖**（不新增广告位、不依赖好友链），奖励以灵石为主并纳入 balance 护栏②复核。

## 2. 目标与非目标

**目标**
- G1 给「每天回来看一眼」一个确定、低门槛、可预期的理由
- G2 用「连续」语义建立损失厌恶（断签即退回到第 1 天）
- G3 七日轮回保证长线不通胀（第 8 天回到第 1 档，而非奖励无限递增）
- G4 累计里程碑给「已坚持 N 天」的成就式正反馈

**非目标（本期不做）**
- 不新增广告位（补签 / 双倍签到都需新位 → 阻塞于字节后台申请，见 §6 R3）
- 不改任何既有数值（不开箱概率、不动境界门槛、不动四条剑冢链）
- 不做弹窗强推（**只在首页入口挂红点**，不自动弹窗打断玩家）
- 不做时区/服务器时间校验（沿用本地自然日 `todayString()`，与既有每日重置同口径）

## 3. 数值设计（拟新增数值假设 #53）

### 3.1 七日轮回奖励表

| 连续天数 | 灵石 | 机缘 | 灵材 | 备注 |
|---|---|---|---|---|
| 1 | 100 | — | — | 首档即正反馈 |
| 2 | 150 | — | — | |
| 3 | 200 | — | — | |
| 4 | 250 | — | — | |
| 5 | 300 | — | — | |
| 6 | 350 | — | — | |
| 7 | 800 | 10 | 灵草 ×2 + 灵石髓 ×1 | 周期大奖（轮回节点） |

- **轮回**：第 8 天回到第 1 档，`cycleDay = ((streak - 1) % 7) + 1`
- **日均摊**：灵石 (100+150+200+250+300+350+800)/7 = **≈307/日**；机缘 10/7 ≈ **1.43/日**；灵材 3/7 ≈ **0.43/日**
- **护栏②影响**（#38 基线：日净收入 ≤9500 / 灵材 ≤37 / 机缘直接投放 ≤120；实测 5305–6563 / 灵材 30–31 / 机缘 95）：
  签到后 ≈ 5612–6870 / 灵材 ≈31 / 机缘 ≈96 —— **全部仍在既有上限内，无需抬基线**；
  但**必须**在 `tests/balance.test.ts` 的「典型一日」模拟里接入签到收入并补断言（§6 J3）

### 3.2 累计里程碑（一次性，不入日循环口径）

| 累计登录 | 奖励 |
|---|---|
| 7 天 | 灵石 500 |
| 15 天 | 修真宝盒券 ×1 |
| 30 天 | 机缘 30 + 灵草 ×5 |

- 幂等领取（`milestonesClaimed` 记录已领天数），跨天不补发
- 一次性发放：与「妖径首通奖 / 秘境段位周奖日均摊」先例同口径，**不按日均摊计入 #38**，但在 balance 补一条「领取日」用例确保不击穿单日上限（最坏：30 天档当日机缘 +30，加上第 7 天轮回档 +10 = 40，远低于 120）

### 3.3 断签规则

- `dayGap(lastDay, today) === 1` → `streak += 1`（正常续签）
- `dayGap > 1`（断 1 天以上）→ `streak = 1`（经典重置）
- 同日重复领取 → `canClaim = false`，无奖励（幂等由 `lastDay === today` 保证）

## 4. 实现设计

### 4.1 纯函数模块 `core/checkin.ts`

> 与 `core/boxAuto.ts` / `core/path.ts` 同层，**零 `import 'cc'`**，可脱离引擎单测。

```ts
export const CHECKIN_CYCLE = 7;
export interface CheckinReward { lingshi: number; jiyuan: number; mats: Record<string, number>; }
export const CHECKIN_REWARDS: CheckinReward[];              // 7 项，见 §3.1
export const CHECKIN_MILESTONES: { days: number; ... }[];    // 7 / 15 / 30，见 §3.2

export interface CheckinView {
    /** 连续天数（领取后）；未领取过 = 0 */
    streak: number;
    /** 轮回内第几天（1..7），0 = 尚未领取过 */
    cycleDay: number;
    /** 今日是否已领 */
    claimedToday: boolean;
    /** 今日是否可领（lastDay !== today） */
    canClaim: boolean;
    /** 今日可领的奖励（canClaim=false 时为 null） */
    pending: CheckinReward | null;
    /** 累计登录天数 */
    totalDays: number;
    /** 下一个未领里程碑（null = 全部领完） */
    nextMilestone: { days: number; ... } | null;
}

export function dayGap(from: string, to: string): number;   // 解析 YYYY-MM-DD，跨月跨年安全
export function checkinView(save: SaveData, today: string): CheckinView;
/** 领取：返回本次实发奖励并写存档；不可领（已领）返回 null —— 幂等 */
export function claimCheckin(save: SaveData, today: string): CheckinReward | null;
/** 领取累计里程碑（days 指定），返回 false = 未达标/已领过 */
export function claimMilestone(save: SaveData, days: number): boolean;
```

发奖统一走既有账本：`EconomySystem.addLingshi` / `addJiyuan` + `AlchemySystem` 灵材入库（与 #41 历练掉落同路径），**不新开加钱口子**。

### 4.2 存档 v9

```ts
export interface CheckinState {
    /** 上次领取日期 YYYY-MM-DD（'' = 从未领取，首日即可领第 1 档） */
    lastDay: string;
    /** 连续天数（断签重置为 1） */
    streak: number;
    /** 累计登录天数（只增，里程碑依据） */
    totalDays: number;
    /** 已领取的里程碑天数（幂等） */
    milestonesClaimed: number[];
}
```

- `saveModel.ts`：`version: 8 → 9`、`defaultSave()` 补 `checkin`、`migrate()` 版本白名单增 9 + `migrateCheckin(raw)`（非法值钳制：`streak/totalDays` 取非负整数、`milestonesClaimed` 去重排序、`lastDay` 非字符串回退 `''`）
- **迁移必须写 `Array.from(new Set(...))` 而非 `[...new Set(...)]`** —— 本项目降级编译把展开编成 `[].concat(...)`，concat 不展开 Set，产物里会变成 `[Set]`（M24 踩过，见 `migrateTrail` 注释）
- **不新增 `daily` 字段**，故 `EconomySystem.dailyReset()` 无需改动

### 4.3 页面 `scenes/CheckinScene.ts`

- `pageBackground` + `pageHeader('每日问道', back)` + `statusBar(n, DESIGN_H/2 - 226)`
- 顶部：连续天数大字 + `已连续问道 N 天`（第 7 天附「明日轮回」提示，避免玩家误以为断了）
- 中部：**7 格单排**（每格 84 宽 / 间距 6，总宽 624，居中，不出安全区），格内 = 「第 N 天」+ 奖励要点 + 三态：
  | 态 | 判定 | 样式 |
  |---|---|---|
  | 已领 | `idx < cycleDay`（本周内）或今日已领 | 打勾 + 墨色 |
  | 今日可领 | `idx === cycleDay && canClaim` | 金色高亮 + 脉动 |
  | 未到 | `idx > cycleDay` | 置灰 |
- 下部：累计里程碑 3 行（「累计 7 天 / 15 天 / 30 天」+ 进度 + 已领标记），达标未领显示「领取」按钮
- 底部：主按钮「领取今日机缘」（文案随奖励变，如「领取今日 · 灵石 300」）；不可领时置灰（`UIOpacity`，**不用 `setEnabled(false)`** —— 见踩坑 R1）
- 纯展示 + 两个领取按钮，无跳转

## 5. 边界与风险

| # | 风险 | 对策 |
|---|---|---|
| R1 | 置灰按钮用 `setEnabled(false)` 会让回调**永久失效**（M22 踩过：`towerChargeMiss` 分支不可达） | 置灰一律 `UIOpacity` |
| R2 | 降级编译把 `[...new Set()]` / `[...map.entries()]` 编成 `[].concat(iterator)`，产物取值恒 undefined（M24/M25 踩过） | 新增收集逻辑一律 `Array.from` / `Map.forEach`；**验收必须 grep 构建产物** |
| R3 | 补签 / 双倍签到需新广告位 → 阻塞于字节后台（B1） | 本期**不做**，列入候选池待 B1 就绪 |
| R4 | 签到灵石进「典型一日」后击穿 #38 上限 | 日均摊仅 ≈307（占 9500 的 3.2%），预估安全；仍须跑 balance 实测，爆了就降档位而非抬上限 |
| R5 | `dayGap` 跨月/跨年/时区 | 用 `Date.UTC(y, m-1, d)` 解析后按 86400000 整除求差，避开 DST；单测覆盖 2 月闰日 / 跨年 / 跨月 |
| R6 | 老档（v8）迁移后首日即可领第 1 档，老玩家「白得」 | 符合预期（一次性 100 灵石，量级 ≈ 一次前山斩妖），且给老玩家回流的即时正反馈 |
| R7 | 7 格单排挤占宽度 | 624 < 720 且有 48px 边距；`npm run audit:layout` 复检 E1–E5 |
