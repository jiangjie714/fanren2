# M27 新手引导：首日三步手把手 + 可复用引导层脚手架

- **状态**：设计中（2026-10-16）
- **诊断来源**：`docs/项目现状与后续规划.md` §3.7 病灶 3「无首战保护、无新手引导（全码 grep 无 tutorial / 首战保护）」、
  §9.2 未实现清单 **A15**
- **范围**：首次进入首页 → 开箱 → 首次渡劫的三步透视遮罩 + 手势指引
- **硬约束**：**零数值改动**（不发任何奖励、不改任何经济参数）；不动既有页面版式坐标

---

## 1. 目标与非目标

### 1.1 目标

| # | 目标 | 判据 |
|---|---|---|
| G1 | 新玩家首日知道「下一步干什么」 | 首页/开箱页出现指向明确目标的遮罩挖洞 + 文案 |
| G2 | 引导不侵入玩法：不发放奖励、不改概率/门槛 | 全仓 diff 无 `core/config/*` 数值改动（除 `texts.ts` 文案） |
| G3 | 引导层可复用：后续加步骤只改一处表 | `core/guide.ts` 步骤表 + 场景 `guideAnchor()` 两个扩展点 |
| G4 | 可跳过、可自动结束 | 气泡「跳过引导」钮；首次渡劫成功（`realmIndex > 0`）自动结束 |

### 1.2 非目标（明确不做）

- **不做**多分支/条件化剧情引导（YAGNI；三步线性足够覆盖首日）
- **不做**引导专属美术（无新图）：高亮框、指示点、气泡全部 `Graphics` 代码绘制
- **不做**设置页「重看引导」开关（后续需要时再加，届时存 `tutorial.done = false` 即可）
- **不做**补签/双倍等广告位相关（阻塞于 B1）

## 2. 设计决策（含被否决方案）

### D1：引导步骤**由存档状态推导**，不存当前步

`guideStepFor(save, ctx)` 是纯函数：输入存档 + 当前场景上下文，输出应展示的步骤。
**不存 `currentStep`** —— 步骤可由「`realmIndex` 是否为 0 / `canBreakthrough` / 当前场景」完整推导，
存一份反而会出现「存档里的步」与「实际状态」不一致的双源真相。

> 被否决：存 `tutorial.step: number` 线性推进。多一个字段、多一份失效可能，且首日三步完全可推导。

### D2：目标坐标由**场景自报**，不由引导层硬编码

定义 `GuideHost` 接口，参与引导的场景实现 `guideAnchor()`，返回**设计系**矩形或 `null`：

```ts
export interface GuideAnchor { x: number; y: number; w: number; h: number }

export interface GuideHost {
    /** 当前可引导的目标矩形（设计系，中心锚）；null = 此刻不宜引导 */
    guideAnchor(): GuideAnchor | null;
}
```

- 坐标写在场景自己的构建代码旁边 → **场景改版式时坐标不会漂移**（引导层硬编码坐标表是经典腐烂源）
- `null` 语义强大：开箱页在「蓄力/共鸣/结算浮层」打开时返回 `null`，引导自动让位，无需引导层懂 BoxScene 状态机
- 场景未实现 `guideAnchor` → 引导层静默不显示（默认关闭，而非默认全屏遮挡）

> 被否决：引导层维护 `Record<场景名, 矩形>` 硬编码表。漂移风险 + 无法表达「此刻不宜引导」。

### D3：遮罩挖洞用**四矩形拼**，不用 Mask / Shader

Cocos 3.x `Graphics` 无 even-odd 挖洞。四块（上/下/左/右）各是一个 `Node + UITransform + Graphics + Button`：
- `Graphics` 画玄墨遮罩（`faded(THEME.void, 170)`，与 `dimLayer` 同色同口径）
- `Button`（`Transition.NONE`，`target = 自身`）**吸收点击** → 洞区无遮罩 → 点击自然穿透到下层 UI

洞内可点、洞外不可点，无需任何事件转发，也不碰目标按钮自身逻辑（**不**用 `setEnabled`，
遵守项目硬约束「置灰用 `UIOpacity`，禁用 `setEnabled(false)`」）。

### D4：引导层是**覆盖层**，不是 `IScene`

- 挂在 `Canvas` 下、`SceneRoot` **之后**添加（同父下后添加者在上），因此永远盖在页面之上
- 不入 `SceneStack` → 不参与 `push/pop/swap` 生命周期，不会污染返回栈
- `Game.tick()` 每帧调 `GuideLayer.sync()`：`sync` 只做一次字符串 key 比较，
  **key 未变则零开销**，变了才销毁重建（避免每帧重建节点）

### D5：引导结束条件 = 首次渡劫成功 或 主动跳过

- `save.realmIndex > 0`（凡人 → 练气）→ 引导目的达成，自动写 `tutorial.done = true` 并落盘
- 玩家点「跳过引导」→ 立即 `done = true`
- **不做**「开箱 N 次后强制结束」：宝盒攒机缘本来就是首日主线，指到渡劫为止是正确行为

### D6：存档 **bump v10**

`tutorial: { done: boolean }` 放顶层。理由同 M26 的 `checkin`：引导完成是**跨会话持久语义**，
塞进 `daily` 会被每天清掉。只此一个布尔字段（步骤可推导，见 D1）。

## 3. 步骤定义

| 序 | id | 场景 | 触发条件 | 目标（设计系矩形） | 文案 |
|---|---|---|---|---|---|
| 1 | `openBoxEntry` | `HomeScene` | `!canBreakthrough` | 环形「仙缘宝盒」钮 `(-130, -287, 110, 110)`（视觉 96，外扩 14） | 标题「第一步 · 求仙缘」；正文「机缘是突破的根本。点这里进仙缘宝盒，开箱攒机缘。」 |
| 2 | `boxOpen` | `BoxScene` | `phase === 'idle'` | 凡俗卡「开 启」钮 `(-232, -18, 196, 96)`（视觉 182×68） | 标题「第二步 · 开启宝盒」；正文「按住可连开，松手即停。开出机缘，够了就能渡劫。」 |
| 3 | `breakthrough` | `HomeScene` | `canBreakthrough` | 主 CTA「冲击境界」`(0, -68, 508, 110)`（视觉 500×102，外扩 8） | 标题「第三步 · 引动天劫」；正文「机缘已满！点这里冲击境界，首战有天道庇佑。」 |

- 步骤 1 → 2：点洞进开箱页（场景切换 → `sync` 自动换步）
- 步骤 2 → 1 或 3：开箱返回首页后按机缘是否足够自动切换
- 步骤 3 → 结束：渡劫成功回首页 `realmIndex > 0` → `done`

**步骤 2 的「按住可连开」**：复用 #52 已实现的长按连开（M22b 后 C 项），引导文案只做告知，不改交互。

## 4. 数据模型

### 4.1 存档 v10

```ts
// ---------- v10（M27 新手引导） ----------
/** 新手引导进度。放顶层（跨会话持久语义，进 daily 会被每日重置清掉）。 */
export interface GuideState {
    /** 已完成/已跳过；true 后引导永不再现 */
    done: boolean;
}
```

迁移：`migrateTutorial(r.tutorial)` —— 非对象 → `{ done: false }`；`done` 非布尔 → 取真值布尔。
老档（v9 及更早）无此字段 → 缺省 `{ done: false }`，即**老玩家升级后也会看到引导**。
（可接受：老玩家多半 `realmIndex > 0` → 首次 `sync` 即自动判定完成并落盘，不会真的挡路。）

### 4.2 纯函数层 `core/guide.ts`（零 `cc`、零 System 依赖）

```ts
export type GuideStepId = 'openBoxEntry' | 'boxOpen' | 'breakthrough';

export interface GuideStep {
    id: GuideStepId;
    title: string;   // 走 TEXTS
    body: string;    // 走 TEXTS
}

/** 判定上下文：由调用方（引导层）注入，保持纯函数零依赖 */
export interface GuideCtx {
    /** 栈顶场景 node.name */
    scene: string;
    /** 机缘是否够渡劫（Game.realm.canBreakthrough()） */
    canBreakthrough: boolean;
}

export function guideDone(save: { tutorial: { done: boolean } }): boolean;
export function guideStepFor(save, ctx): GuideStep | null;
```

`guideStepFor` 判定顺序：

1. `save.tutorial.done` → `null`
2. `save.realmIndex > 0` → `null`（引导目标已达成；调用方据此写 `done` 并落盘）
3. `ctx.scene === 'BoxScene'` → 询问场景 `guideAnchor()`；非 null 则步骤 2，否则 `null`
4. `ctx.scene === 'HomeScene'` → `canBreakthrough` ? 步骤 3 : 步骤 1
5. 其它场景 → `null`

> 步骤 2 是否显示取决于 `guideAnchor()` 是否返回矩形 —— 这条**不在纯函数里**（需要场景自报），
> 由引导层组合：`step = guideStepFor(...)` 且 `anchor = host.guideAnchor()`，两者都非空才渲染。

## 5. 引导层 `ui/GuideLayer.ts`

### 5.1 结构

```
GuideLayer (Node, 挂 Canvas，尺寸 = 可视区 ×2)
├── maskTop / maskBottom / maskLeft / maskRight   // 四块遮罩，各带 Button 吸点击
├── ring                                          // 金色圆角描边（呼吸 tween：UIOpacity 90↔255）
├── pulse                                         // 洞中心下方指示圆点（scale + opacity 脉冲）
└── bubble                                        // 文案气泡：Graphics 圆角底 + 标题/正文 + 跳过钮
```

### 5.2 关键实现约束（项目硬约束复读）

- **集合收集一律 `Array.from` / `Map.forEach`**，禁用 `[...new Set()]` / `[...map.entries()]`
  （降级编译会变 `[].concat(iterator)`，产物里取值恒 `undefined`，单测测不出）
- **置灰用 `UIOpacity`**，禁用 `setEnabled(false)`
- 遮罩色用 `faded(THEME.void, 170)`（玄墨紫），**不要**旧冷蓝灰
- 全部用 `Graphics` 画，不新增美术资源（背景过高饱和，文字必须有深墨描边才不糊）

### 5.3 气泡择位

**优先放洞的下方**，下方空间不足才上移。理由（实测）：首日两步的目标（宝盒入口 `y=-287`、
主 CTA `y=-68`）**上方都紧邻其它 CTA/横幅**，放上方必然压住主 CTA 那条金带
（首版实现就压住了「冲击境界」下沿）。气泡宽 560、高 148，横向钳在安全区内（±332）；
与洞的间隙 56 —— 要留出脉冲指示点（洞下方 18、半径 15）的位置。

### 5.4 sync 协议

```ts
static sync(): void {
    const host = Game.stack?.top as (IScene & Partial<GuideHost>) | undefined;
    const anchor = host?.guideAnchor?.() ?? null;
    const step = guideStepFor(Game.save, { scene: host?.node.name ?? '', canBreakthrough: Game.realm.canBreakthrough() });
    const key = step && anchor ? `${step.id}@${anchor.x},${anchor.y},${anchor.w},${anchor.h}` : '';
    if (key === this.key) return;         // 每帧比较，未变则零开销
    this.key = key;
    this.rebuild(step, anchor);           // null → 整层 active=false
}
```

`Game.tick(dt)` 末尾加 `GuideLayer.sync()`。

## 8. 风险

| 风险 | 缓解 |
|---|---|
| 引导层遮挡导致玩家卡住（想点别的被吞） | 气泡常驻「跳过引导」钮；任何时刻可跳 |
| 老玩家升级后 `done=false` 莫名弹引导 | `realmIndex > 0` 首次 sync 即自动完成并落盘，实际不会显示 |
| 遮罩 Button 与洞边界计算差 1px 导致洞边缘点不到 | 洞矩形比目标视觉尺寸**外扩 8–14px**（表内已给外扩后尺寸） |
| `audit:layout` 静态解析不认识 `ui/GuideLayer.ts` 的图形 | 审计器按调用点建模；若新增误报，按既有「先怀疑解析规则」手法核对 |
